# Next.js + Supabase scaffold

Stack ID: `nextjs-supabase`. The root `package.json` runs Next.js; `app/` owns pages and layouts; `app/api/` owns HTTP endpoints; `lib/supabase.js` owns the Supabase clients (a fresh server client per request via the SSR cookie helper, one browser client); `middleware.js` refreshes the Auth session cookie on every request; `supabase/migrations/` owns the schema and Row Level Security policies; `test/` holds Vitest tests; `e2e/` holds Playwright, axe and screenshot tests. `scripts/` holds seed/setup utilities. Read `README.template.md`, the existing files and `.env.example` before changing them. Replace the placeholder home screen, not the working runner configuration.

The project's own Supabase project is already connected (see `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` in `.env.local` — the build created this project for real, nobody pastes these by hand). Use the full Supabase surface rather than reinventing a piece of it: **Data** (Postgres tables, migrated with `supabase db push`, every table's access controlled by an RLS policy — never `service_role` from a client component), **Auth** (`supabase.auth.*` for sign up/in, magic links, and OAuth providers including Google — never hand-rolled password hashing or session cookies), **Storage** (a bucket per kind of upload, with its own RLS policy, for images and other uploaded files unless `.agentforge/PLUGIN.md` names another uploads provider), and **Realtime** or **Edge Functions** where the specification actually calls for live updates or logic that must run with the service-role key. Add route files, data models (as migrations + RLS policies, not a Mongoose-style schema file), validation and role enforcement for every approved requirement. Preserve the Tailwind/PostCSS pipeline when editing CSS or package dependencies. `SUPABASE_SERVICE_ROLE_KEY` never reaches a client component or a `NEXT_PUBLIC_*` variable.

The Studio assigns this project's local preview an isolated loopback port. Do not hard-code a port or reuse another project's preview address: the Studio supplies `PORT` when it launches any supported stack.
