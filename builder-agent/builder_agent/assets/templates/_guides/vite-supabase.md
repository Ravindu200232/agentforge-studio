# Vite + Supabase scaffold

Stack ID: `vite-supabase`. Root `package.json` runs a Vite + React single-page app with no server of its own. `src/lib/supabase.js` owns the one browser Supabase client; `src/` holds routes/pages and components; `supabase/migrations/` owns the schema and RLS policies; `test/` holds Vitest tests; `e2e/` holds Playwright, axe and screenshot tests. Read `README.template.md`, the existing files and `.env.example` before changing them.

The project's own Supabase project is already connected (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` in `.env.local`, created for real by the build setup step). **This app has no backend and no secret store**: every environment variable here is public, compiled into the bundle, so `SUPABASE_SERVICE_ROLE_KEY` must never be referenced from this project at all — anything that needs it belongs behind a real server (a Mongo-backed or other server-side stack), not here. Consequently, **Row Level Security is this application's entire security boundary**: every table an authenticated or anonymous user can read or write through `supabase.from(...)` needs a correct RLS policy, and a missing one is a security bug, not a missing feature — treat writing and testing RLS policies as core implementation work, not an afterthought. Use `supabase.auth.*` directly from the client for sign-in (including Google and other OAuth providers), Storage buckets with their own RLS for uploads, and Realtime subscriptions where the specification calls for live updates. Preserve the Tailwind/PostCSS pipeline when editing CSS or package dependencies.

The Studio starts the local Vite preview on an isolated port for this project. It supplies `PORT`, so do not hard-code a port or assume that another project is stopped first.
