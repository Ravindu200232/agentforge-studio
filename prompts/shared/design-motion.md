## Design and motion guidance

Follow the approved product, brand and design. In the prototype, use these principles to make design decisions the product leaves open. In the build, preserve the approved prototype's look, timing, feedback and reduced-motion behavior while connecting real application state. Use original, reusable UI and implement each effect in the stage's own stack.

- **Frontend design, brand, themes, canvas and web artifacts.** Choose a visual direction from the product's subject and audience. Define a typography hierarchy, spacing scale, semantic color roles and a few original visual details. Use the customer's brand tokens, or derive them from the approved theme. Maintain contrast, legibility, coherent layout, native semantics, visible focus and responsive density. Review actual screens against the brief. Use original illustrations, editorial compositions or deterministic generative art only when they serve the content.
- **Motion direction, principles, shot composition and color.** Give motion a purpose and one consistent character. Direct attention with hierarchy, sequencing, easing and spacing. Pick durations and easing once and reuse them as tokens. Anchor transitions to the control or object that triggered them. Keep background motion subordinate and provide a static frame that stands on its own.
- **Micro-interactions and page transitions.** Give controls accessible hover, focus, pressed and disabled states. Show pending, success, error and undo when the workflow calls for them. Route changes preserve back/forward, scroll and focus behavior. Use CSS transitions, keyframes or the Web Animations API for small effects. Where a native View Transition helps, feature-detect it and ensure navigation works immediately without it.
- **Accessible motion and smooth rendering.** Honor `prefers-reduced-motion` in both CSS and JavaScript, including preference changes when there are ongoing animations. Replace large movement, loops or parallax with gentle fades or immediate updates. Keep state changes, focus and labels intact in reduced motion. Prefer opacity and transforms over layout or paint work. Batch DOM reads and writes, pause work offscreen and cancel animations, timers, observers and listeners when a view exits. Test keyboard use, both motion preferences and a narrow viewport.
- **SVG, logos, type, glass and backgrounds.** When approved, use small native SVG effects or CSS for a logo reveal, restrained typographic animation or decorative background. Keep real text selectable and readable, keep decoration out of the accessibility tree and give transparency and blur a solid high-contrast fallback.
- **Charts, infographics, maps and illustrations.** When the product requires them, design a legible static view first. Animate changes between real values or locations without changing the scale, hiding labels or obscuring meaning. Give users readable values and a static equivalent. Use a seeded composition and a still fallback for any procedural visual. Use canvas, particles, shaders or 3D only when they serve an approved feature and can meet its accessibility and performance needs.
- **Specialized motion production.** Use the source pack for a relevant technique only when the approved deliverable calls for it, such as a timeline, Lottie asset, 3D scene, onboarding video, explainer, kinetic typography or media export. Translate the technique to native browser primitives for the HTML prototype. In the build, use the selected stack and the lightest suitable implementation. Keep videos, effects and dependencies out of ordinary UI unless the approved product needs them.
