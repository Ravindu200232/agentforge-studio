### Author the preview app

Inspect the destination. Start from the approved requirements when application files are absent. On a resumed run, keep completed work, then finish missing or broken files. Write `index.html` with an accessible title, a `root` mount and a module entry for `/src/main.tsx`. Write `src/main.tsx` to mount React and import `src/index.css`. In the entry or `src/App.tsx`, use `import.meta.glob('./pages/**/*.{tsx,jsx}', { eager: true })` to collect the page modules. Key them by the path relative to `src/pages`, without the extension, to match `routes[].file`. Pass that object to `<Router pages={pages} />` inside `<SessionProvider>`. Read `@/lib/router`, `@/lib/session`, `src/routes.ts` and `src/demo.ts` before wiring navigation and sign-in. The Studio provides these modules, the `@/` alias and the Vite bundler.

Write your styling entry and, when using Tailwind utilities, author `tailwind.config.cjs` and `postcss.config.cjs` for Tailwind CSS 3 with React source paths. Define the visual tokens in one place. Write shared components in `src/components/`, route screens in `src/pages/`, and shared state in `src/lib/`. Keep route files thin and split feature behavior from presentation when it makes a feature easier to change. Each route screen exports its component as default. Use the Studio's route table rather than duplicating it.

Check that the entry imports real files, routes can mount, keyboard navigation works, and forms show helpful feedback. Keep application and demo code separate. Use React, TypeScript, semantic HTML, CSS, and existing compatible packages. Generate project-specific UI from scratch and avoid copying starter applications, component kits, or packaged design blocks. The Studio installs dependencies and bundles the preview.
